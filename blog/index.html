WebMCP-Edge · implementation findings

Turning a website into an agent-native interface

A zero-backend WebMCP prototype on the AI Engineering Visual Encyclopedia.

Implementation findings. The implementation has local automated validation; native browser-agent evaluation has not been run. No performance advantage is claimed.

The website already knows what it contains

Ask an agent to find CUDA concepts about GPU memory. Through the ordinary interface, it must discover navigation, interpret the Atlas domains, open entries, and reconstruct which titles and explanations belong together. The site already has those relationships in its content model.

WebMCP offers a way to declare them as capabilities. Instead of asking an agent to infer every operation from presentation, a page registers tools that call application logic and return structured data. The research question is what changes at this boundary, not whether one small prototype proves that browser agents are universally better.

One content model, three operations

The prototype projects existing CUDA and Inference Atlas exports into namespaced records. It does not scrape the DOM or maintain demo articles. Titles, summaries, technical points, domains, and scene relationships come from the encyclopedia source.

The actual MVP boundary
ToolBehavior
search_articlesBounded deterministic lexical search; structured titles, summaries, IDs, and links.
get_articleCanonical record from the source exports, with technical points and scene metadata.
cite_articleTitle-first citation using actual title and canonical URL; missing bibliographic facts remain missing.

Search and retrieval can reveal a matching entry in the mounted Atlas. They do not navigate to another world or alter a simulation. The human sees the same application, with a second interaction vocabulary.

    Native execution and the local harness are separate modes. The harness calls our application functions. Native mode discovers a RegisteredTool object through document.modelContext, passes it to executeTool, and displays the browser's serialized result. A harness result is not proof that a browser agent can discover the tools.
    What has actually been established?
    218 tests passed across 13 suites, including six new WebMCP tests. The TypeScript check and production subpath build passed.
    Local tests validate the real-content projection, identifiers and destinations, search limits, malformed arguments, deterministic citations, and mocked registration/cancellation behavior. The full inherited suite also runs, protecting simulation and content contracts.

    The protocol defines three tasks: CUDA memory hierarchy; three relevant inference KV-cache/memory concepts; and retrieval plus an APA citation. A fair end-to-end comparison needs the same agent/model, source revision, task, and browser conditions, with independent runs and all failures retained. Until those runs exist, the comparison remains architectural.
    Declared does not mean trustworthy
    A schema constrains the shape of inputs. It does not authenticate the caller, establish authority, or prove that a page's descriptions are honest. Tool descriptions and returned content enter the agent's interaction surface.
    This experiment changes no content and makes no external requests. It has no model API, server, secrets, or remote telemetry. Temporary selection changes are disclosed; the adapter does not assert readOnlyHint because the draft describes that hint as modifying no state. Local logs are bounded and recorded only while research mode is open; exported inputs need review before sharing.
    The scope is deliberately narrow. Lexical substring search is not semantic retrieval. Only CUDA and Inference Atlas entries are included. Missing author/publication dates limit citation completeness. Mocked registration does not verify origin mediation, real browser cleanup, or native agent behavior.
    The specification reviewed is the Draft Community Group Report dated 2 October 2026. It is not a W3C Standard and is not on the W3C Standards Track. Browser support and draft interfaces may differ.
    Reproduce the implementation
    The companion research package contains a patch over the pinned encyclopedia revision, a setup script, the evaluation protocol, and validation evidence. It is available in the private research repository. The evaluation protocol and integration design document what is implemented and what remains to be tested.
    bash scripts/reproduce.sh /tmp/webmcp-review
cd /tmp/webmcp-review
npm ci
npm test
npm run build
npm run dev
    Open an Atlas, expand “Agent-native web · research mode,” and run a local search. To evaluate native integration, use a verified experimental browser with the matching draft API. The panel reports unavailable support rather than installing an imitation API.
    The architectural observation is modest: the site can expose its own content relationships as explicit operations. Whether that reduces agent effort, improves relevance, or creates new failure modes requires the browser experiment still ahead.
